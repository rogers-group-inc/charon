## cross-cutting/schema-change

**What it is:** the checklist for any `prisma/schema.prisma` change. Steps moved verbatim from
TOUCHES.md "When you change the Prisma schema" (pointers updated to the skills).

1. `prisma migrate dev --name <change>` (or `migrate diff` for the SQL) and commit the
   migration.
2. Update affected services + this index + `charon-domain-model` (Definitions bullet + Schema
   block).
3. If you added a secret field, register it in `integrationConfig.SECRET_FIELDS`.
4. Re-run `npm run typecheck && npm test`.

**Writers:** `prisma/schema.prisma`, `prisma/migrations/`.
**Readers:** the generated client (`src/generated/prisma`, regenerated by `postinstall`);
`src/db.ts` (Prisma client singleton via `@prisma/adapter-pg`).

**Invariants:**
- Migrations and seeds never carry real data, hostnames or secrets (rule 7).
- After a merge that changed the schema, run `npx prisma generate` on main before typechecking.

**When changing this:** scale-check per-endpoint queries at 100 and 2000 endpoints — a
`for…of rows { await prisma…update() }` loop or an unselective `findMany` in a ticking job is
the usual failure at the top end.
